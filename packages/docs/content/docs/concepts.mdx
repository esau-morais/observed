## Base and candidate

The **base** is your code before the agent's change. The **candidate** is your code after it. Observed runs your app on both and compares them, so every result is about what this change did.

## Journeys

A **journey** is a scripted walk through your app, like adding an item to the cart and paying. Observed runs each journey on both revisions and records screenshots, network requests, browser errors and timings. That record is the **evidence**.

## Checks

A **check** is a rule about the evidence, like "one click sends one POST /orders" or "no new browser errors". See [Checks](/docs/checks) for the kinds.

A check counts only if it exists at the base revision. An agent can add or edit checks, but its edits apply from the next change on, so it never grades its own work.

## The judge

The **judge** reads the evidence, applies the checks and decides what holds. It is plain code with no model in it, and it imports no model SDK.

Each line on a receipt is in one of four states:

| State   | Meaning                                                                                               |
| ------- | ----------------------------------------------------------------------------------------------------- |
| Checked | A check from the base revision passes on the candidate.                                               |
| Changed | The screenshot or the total request count differs. These lines set no verdict, so you decide.         |
| Unknown | Evidence is missing, skipped or was altered, or the check has no baseline, so the judge can't decide. |
| Failed  | A check fails on the candidate.                                                                       |

Unknown is never rounded up to a pass. A check has no baseline when the change adds it, alters its journey or alters its test file. It also has none when Observed could not read the base revision's `observed.json`, or in a preview, which captures only the candidate. Such a check prints as unknown when it passes and as failed when it fails. The last line is the judge's conclusion, except that it says "Nothing checked" instead of "No regression" when no line is checked. The `result.json` that Observed [stores](#where-evidence-lives) keeps the judge's own conclusion. A receipt with a checked line still ends in "No regression" even when other lines are unknown.

A journey only shows the cases it ran, so Observed says "observed", never "proved".

## Gaps

<Callout title="In progress">Gap closing is planned for a later milestone.</Callout>

A **gap** is changed code that no journey reaches. When there is one, the agent proposes a journey for it and Observed runs that journey before showing you results. A gap that stays open shows as a short note on the receipt, not a task for you.

## Laws

<Callout title="In progress">Laws are planned for a later milestone.</Callout>

**Laws** are sentences about what must stay true, taken from the chat, issue or PR text you already write. Once a person accepts a law it is locked, and like a check it is judged at the base revision. An agent's edit to a law changes no verdict until a person merges it.

## Where evidence lives

Observed stores each result as `result.json`, with the captures it judged, in a record in the hidden ref `refs/observed/evidence`. Each record sits under the commit it judged, and its name is the SHA-256 of its files. Records never appear in your working tree, your index or your diffs.

Git does not push or fetch that ref unless you ask. To share your evidence, push it:

```sh
git push origin 'refs/observed/*:refs/observed/*'
```

To get it in another clone, fetch it:

```sh
git fetch origin 'refs/observed/*:refs/observed/*'
```

To fetch it on every `git fetch`, add the refspec to the remote:

```sh
git config --add remote.origin.fetch 'refs/observed/*:refs/observed/*'
```

The refspec has no leading `+`, so git refuses a push or fetch that would rewrite the ref's history unless you force it. Observed only adds records. Before it reads one, it checks that no commit on the ref changed or removed a record and that every record still matches its SHA-256 name. If either check fails, it reads nothing. Observed does not catch a forced rewrite that drops a record entirely, so that commit reads as having no record.

A clone that has fetched the ref prints the same receipt as the clone that wrote it, with `observed receipt` from the [CLI](/docs/cli).

If two clones write records before either pushes, the second push is rejected, and Observed can't merge the two histories yet. Write records from one place, such as CI.

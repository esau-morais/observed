---
title: Gate corpus
description: Pairs of revisions with known outcomes, and the checker that reads their raw files.
---

The gate corpus is a set of small apps, each committed as a base and a candidate whose outcome is known in advance. `observed run` captures and judges every pair. A separate checker then compares the result with the raw files Playwright and the app wrote. The checker imports no Observed code, so a judge or collector bug can't hide behind its own output.

## Run it

Install Chromium for Playwright once, then pick a new directory for every run:

```sh
bun install --frozen-lockfile
bunx playwright install --with-deps chromium  # from packages/runner
bun run gates /tmp/corpus-01
bun run gates:missing /tmp/corpus-01/correct-change/run /tmp/missing-01
bun run gates:faults /tmp/faults-01
```

To run one pair, add its ID, such as `bun run gates /tmp/corpus-02 request-fault`. To check a kept pair again without running Observed:

```sh
bun run gates:check /tmp/corpus-01/request-fault/run \
  /tmp/corpus-01/request-fault/expected.json \
  /tmp/corpus-01/request-fault/exit.json
```

For each pair the runner creates a Git repository, commits the base and the candidate, and then commits the expectation, before anything is captured. `required-hashes.json` pins the expectation, the checker and the tool's own commit. The pair directory keeps the commits, the command output, the exit code, every capture and the checker's result. `summary.json` lists the results, and the command exits 1 if any pair fails.

Screenshots, timelines and coverage are observations: they never fail a check. Their pairs must keep the named checks passing and exit 0.

## Seeded faults

`gates:faults` needs a clean, committed checkout and GNU `timeout`. It first runs every pair, the missing-evidence probes and two availability probes on the unchanged commit. Then it clones that commit once per fault, changes exactly one expression in the judge or the runner, and runs the probe that must catch it:

| Fault                       | Change                                                     | Caught by           |
| --------------------------- | ---------------------------------------------------------- | ------------------- |
| `passing-above-unavailable` | A passing journey hides another journey's unavailable base | Availability probes |
| `unavailable-as-passing`    | An unavailable journey concludes as no regression          | Availability probes |
| `regression-as-passed`      | A regression verdict becomes passed                        | `request-fault`     |
| `collector-drops-requests`  | The runner records no requests in `observations.json`      | `request-fault`     |

A fault counts as caught only when the checker reports exactly the failures listed for it in `fault-cases.ts`. A crash, an unreadable file or an extra failure does not count. `summary.json` says `complete: true` and `passed: true` only when every fault was caught.

CI runs `gates:faults` in the Corpus workflow on pull requests that touch the judge, the runner, the CLI or the corpus, and on every push to main. It is not a required check.

## Not covered

- Change scope and the change map stay on the `legacy` branch until gap closing, so pairs no longer assert which changed lines ran. That also removes the coverage pair and the generated-journey pairs.
- Pairs don't check the wording of `observed receipt`. The receipt has its own tests in the judge.
- A pair that changes `source`, `setup` or `start` does not exist yet.
- One fault per check kind is covered, not every option of every kind.
